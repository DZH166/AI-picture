# 技术架构与模型方案

## 技术栈
React + TypeScript + Vite；Web Worker 处理 CPU 密集任务；Canvas/必要时 OpenCV.js；ZIP 库导出；IndexedDB 仅保存必要任务元数据；Vitest、ESLint、Prettier、TypeScript strict。

## 处理架构
本地读取图片 → DeepSeek Provider（仅当实际 API 支持视觉输入）→ 水印区域 mask → 真实 inpainting provider → 卡通人物实例分割 provider → 每个人物独立 mask → RGBA PNG → 质量检查 → ZIP/本地下载。MVP 不建立自有 GPU 服务器。

## DeepSeek adapter
独立实现 DeepSeekProvider，配置 apiBaseUrl、apiKey、modelId、timeout、重试、图片大小限制和能力标记。用户提供的模型标识 `deepseekv4.1flash1017` 作为可编辑默认值，但必须确认它是 API 接受的精确 model ID。阅读官方文档 https://api-docs.deepseek.com/zh-cn/ 和真实请求样例；不能猜 endpoint、图片字段或响应结构。
如果模型只输出文字，可以辅助分析/返回候选坐标；文字和矩形框不能伪装成像素级 mask。如果支持图像输出，也需验证是否能可控编辑、输出 alpha、分离每个人物。

## 水印修复
水印定位可结合 OCR/文字区域检测、规则、模型建议和人工修正。修复使用真实 inpainting provider；保留前后对比，不覆盖原图。水印压在脸、服饰、手部或轮廓时标记复核。不能宣称恢复了真实原始像素。

## 人物分割
评估轻量实例分割模型，或检测框 + 提示式分割器。普通背景移除通常只取一个主体，不适合密集拼图；真人检测模型可能无法识别卡通人物。浏览器 CPU/WebGPU/ONNX 方案要实测速度、内存、兼容性和许可。没有真实模型时 UI 必须明确标注，不得假装成功。
