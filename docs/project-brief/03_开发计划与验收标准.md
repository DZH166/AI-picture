# 开发计划与验收标准

## 阶段 1：工程骨架
- 初始化 React + TypeScript + Vite。
- 页面：主任务、设置、结果。
- 多图选择、缩略图、移除输入、导出模式。
- 定义 DeepSeekProvider、WatermarkRepairProvider、CharacterSegmentationProvider。
- 加 mock provider，但 UI 必须标明它是测试数据，不能冒充真实 AI 结果。
- 配置 lint、typecheck、test、build。

## 阶段 2：DeepSeek API
- 按官方文档实现 API 请求，配置 model ID、Base URL、Key。
- 提供测试连接和测试视觉输入。
- 验证图片传输方式、返回格式、超时、重试和错误码。
- 日志不记录 Key、Authorization header 或 base64 图片。
- 如果当前环境无法核验官方文档，先实现接口和设置页，并向用户索要真实请求示例，不得捏造格式。

## 阶段 3：修复与分割
- 定义 mask 格式、坐标系、RGBA 合成函数。
- 实现修复/分割 provider 接口。
- 未接真实模型时，明确显示“尚未配置真实修复/分割模型”。
- 测试透明 PNG、空 mask、越界坐标、尺寸缩放。

## 阶段 4：批处理与导出
- 队列、真实进度、失败重试、保留已完成结果。
- 按原图分类/汇总两种导出。
- ZIP 和 CSV 报告。
- 文件名清理、重名处理；单张失败不影响整批。

## 阶段 5：真实样本测试
使用授权图片覆盖：轻水印、重复半透明水印、水印覆盖人物、人物紧邻/重叠、小人物、多画风、多尺寸。
记录漏检、粘连、边缘破损、修复伪影、每图耗时、API 费用、人工修正时间。

## 最终验收
npm install、npm run dev、npm run typecheck、npm run lint、npm test、npm run build。
Key 不硬编码/写日志；外发图片前有提示；输出 PNG 有 alpha；不为人物建子文件夹；README 说明数据流、限制和许可。无法执行的测试要明确报告，不得声称通过。
