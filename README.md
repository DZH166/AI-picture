# 素材工厂 · 本地第一版

版本 **0.1.0**。这是在本机浏览器中运行的中文素材处理工具，已实现图片批量导入、纯色背景候选提取、透明 PNG 预览与导出。当前交付为本地项目，尚未部署到公网。

第一版适合先验证真实素材是否能被分离、员工操作是否顺手，以及导出目录是否符合工作习惯。**本地试提取不去水印；完整 AI 水印修复和复杂人物分割尚未接入。**

## 安装与启动

本机依赖已安装，可以直接双击 **`启动素材工厂.cmd`**。它会启动本地服务并打开浏览器；使用期间保留启动窗口，结束时按 `Ctrl+C`。

先安装 Node.js 与 npm，在项目目录打开终端：

```powershell
cd "D:\AI素材工厂\ai-material-factory"
npm install
npm run dev
```

保持终端运行，在浏览器中打开终端显示的地址，通常为 `http://127.0.0.1:5173`。端口被占用时以实际输出为准。停止服务可在终端按 `Ctrl+C`。

本版本不需要 GPU、数据库、后端服务或 API Key 即可使用本地提取。首次安装依赖需要联网；本地图片处理本身不调用外部模型。

项目同时附有 `pnpm-lock.yaml`。使用 pnpm 的环境可执行 `pnpm install`、`pnpm dev`；选择一种包管理器完成安装即可。本次开发环境提供 pnpm 和 Node.js，未提供 npm，因此也可直接运行已安装的工具：

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1
```

## 从示例开始

1. 点击「试用示例」或「载入示例」，也可拖入自己的 PNG、JPG、WebP 图片。
2. 保持「本地试提取」，点击「开始本地提取」。队列会显示当前步骤、完成数量、失败原因和耗时。
3. 打开「素材结果」，放大检查透明背景、人物完整性和多余区域。可删除不需要的候选，也可单独下载 PNG。
4. 选择「按原图分类」或「全部汇总」，点击「导出全部素材」下载 ZIP。支持文件夹选择 API 的浏览器还会显示「保存到文件夹」。

处理过程中可以停止，已完成的结果会保留。失败任务可在队列中单独重试。如果已成功提取但想调整参数，请在结果组点击「重新提取」，再回到队列调整参数并开始；这会清除该组旧的候选结果，保留原图。

**刷新或关闭页面会清空本次图片、队列和结果，请先导出需要的素材。** 软件不会修改磁盘上的原图。

## 两种处理模式

| 模式       | 当前行为                                                         | 使用范围                                 |
| ---------- | ---------------------------------------------------------------- | ---------------------------------------- |
| 本地试提取 | 在浏览器 Worker 中按像素颜色与连通区域提取候选，生成真实透明 PNG | 背景较纯、人物彼此分离的卡通拼图         |
| 完整 AI    | 明确显示模型未配置；开始处理时给出失败原因                       | 等待接入真实水印修复与逐人物像素分割模型 |

本地算法从图片边缘估计背景色，只移除与边缘连通的近似背景。已带完全透明像素的图片优先沿用原有透明通道，此时背景容差不参与提取。

参数含义：

- **背景容差**：增大后会移除更多近似背景色，也可能影响与背景相近的角色边缘。
- **最小区域面积**：过滤小碎片；数值过大也可能过滤小人物或配件。

本地算法生成的是连通区域候选，不理解人物身份。相连人物可能合成一张；独立配件可能被拆成另一张；封闭的背景孔洞、抗锯齿边缘、阴影、渐变或复杂背景可能残留。水印不会被专门定位或修复，遮挡内容不会被补全。每个结果都需要人工复核。

## 图片与处理限制

- 当前队列最多 **30 张**，单张最多 **25 MB**（代码按 `25 × 1024 × 1024` 字节检查）。
- 支持 PNG、JPG/JPEG、WebP，并检查实际文件头和能否解码。
- 原图至少 8 × 8 像素，总像素不超过 4000 万。
- 处理时最长边限制为 **1600 像素**，超过时等比缩小。**输出 PNG 基于缩小后的处理尺寸，不是原图分辨率。** 结果页会显示处理尺寸与缩放说明。
- 单图最多保留 256 个候选，并限制累计输出像素量；触发限制会给出说明。
- 单张图的本地分割线程超过 60 秒会中止并提示重试。
- 在解码前解析 PNG、JPEG 和 WebP 的尺寸，提前拒绝超过像素限制的图片。

图片、处理像素和 PNG 结果保存在当前页面内存中，没有图片历史库、断点恢复或跨设备同步。多位员工可分别在自己的电脑上运行，当前版本没有账号、共享队列或多人协作服务。

## 导出内容

每个保留的候选导出一张透明 PNG，不会为单个人物再建立一层文件夹。两种整理方式都包含 `report.csv`：

**按原图分类**

```text
原图A/
  原图A_001.png
  原图A_002.png
原图B/
  原图B_001.png
report.csv
```

**全部汇总**

```text
原图A_001.png
原图A_002.png
原图B_001.png
report.csv
```

ZIP 内没有额外的 `output` 顶层目录。同名原图、同名人物和文件名清理后的冲突会自动编号；Windows 保留名与非法字符会被处理。直接保存到文件夹时，也会避让已有文件和目录。

CSV 包含原图名称、处理状态、保留人物数量、耗时（毫秒）和备注，使用 UTF-8 BOM，处理了引号、换行和常见公式注入字符。可以单独下载报告；部分原图失败不会阻止已经完成的素材导出。

## DeepSeek 连接与图片隐私

设置页提供「测试连接」和「测试视觉输入」，两者独立于本地提取。

官方更新日志确认 `deepseek-flash` 支持视觉理解，并在 2026-10-17 更新为 DeepSeek-V4.1-Flash-1017。项目保留需求文档中原始填写的 `deepseekv4.1flash1017` 作为初始值；该字符串尚未确认是有效 API ID。设置页可以点击「填入官方已核验 ID」切换为 `deepseek-flash`，再用真实账户验证。[DeepSeek 官方更新日志](https://api-docs.deepseek.com/zh-cn/updates/)

使用步骤：

1. 打开「模型与设置」，填写 API Base URL、Model ID 和自己的 API Key。
2. 点击「测试连接」，读取服务方返回的模型列表，并检查当前模型是否存在。
3. 如需测试视觉输入，开启「允许发送图片到配置的 API」。
4. 点击「测试视觉输入」，阅读发送确认弹窗。确认后只会发送内置「森林伙伴」示例图，不会发送你导入的图片；取消则不发送。

当前视觉请求使用文档规定的 `image_url` 格式，显示接口返回的文字描述。请求可能产生服务方 API 费用。**开发时没有真实 API Key，尚未完成真实账户连接、实际费用或视觉效果验证。** 已有接口测试使用模拟响应，不代表真实 API 已连通。图片理解成功也不代表水印修复或人物像素分割已经可用。

隐私与凭据行为：

- 本地提取不外发图片。
- API Key 仅放在当前页面内存中，刷新后需要重新输入；保存设置不会保存 Key。
- API 地址、模型 ID、超时与图片外发开关可以保存到浏览器 `localStorage`。
- 这是纯前端应用。点击 API 测试后，浏览器会把 Key 发送给配置的 API 地址；当前浏览器使用者能通过开发者工具查看 Key。因此应使用自己信任的地址和账户。
- 本版本无需配置 `.env`。不要把真实 Key 写进 `VITE_*` 环境变量或源码，因为前端构建内容可被浏览器读取。
- 浏览器跨域限制、网络限制、无效模型 ID 和账户权限均可能导致连接失败；错误信息会显示在设置页。
- 测试期间锁定配置，可随时取消；离开设置页会中止测试。确认弹窗与请求使用同一份配置，避免地址和授权状态不一致。

## 开发检查与构建

在项目目录运行：

```powershell
npm run typecheck
npm run lint
npm test
npm run build
```

`npm run build` 会先执行类型检查，再输出静态构建到 `dist`。本地查看构建产物：

```powershell
npm run preview
```

预览默认只监听 `127.0.0.1`，不等于公网部署。可选的 `npm run format` 会使用 Prettier 修改项目文件格式。

在仅有 pnpm 的环境，上述命令可对应换成 `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`、`pnpm preview`。依赖已安装时也可直接调用工具进行检查：

```powershell
node node_modules/typescript/bin/tsc -b
node node_modules/eslint/bin/eslint.js .
node node_modules/vitest/vitest.mjs run
node node_modules/vite/bin/vite.js build
```

最后一条直接调用 Vite 的命令只构建前端，类型检查需要单独执行。具体测试结果与待验证项见 [验收记录](docs/acceptance.md)。
